# Бриф для дизайнера: страница транзакций (legacy-style)

Документ описывает **что должно быть на экранах и какие у этих элементов задачи**. Размещение, размеры, цвета, типографика, радиусы, тени, иконки — всё на усмотрение дизайнера. Поведенческие детали и edge-cases описаны в соседнем файле [`legacy-transactions-spec.md`](./legacy-transactions-spec.md), его стоит прочитать перед началом работы — там объяснён смысл каждого взаимодействия, нюансы валидации и логика фильтров.

---

## 1. Главный экран — список транзакций

Назначение: дать пользователю быстро увидеть все денежные операции, отфильтровать и найти нужное, вызвать создание новых, отредактировать или удалить существующие.

### 1.1. Шапка экрана

Элементы:

- **Поиск** — поле ввода. Поиск идёт по описанию транзакции, имени счёта, имени категории, имени контрагента и по сумме (как по подстроке).
- **Кнопка-тоггл фильтров** — открывает/прячет панель фильтров. Помечена индикатором, если активен хотя бы один фильтр; индикатор показывает количество активных фильтров.
- **Три кнопки создания** — «Приход», «Расход», «Перевод». Каждая открывает форму создания соответствующего типа. «Перевод» неактивен, если у пользователя меньше двух счетов.

### 1.2. Панель фильтров

Скрывается/показывается тоггл-кнопкой, состояние видимости запоминается между сессиями.

Элементы (каждый — отдельный фильтр-чип, у каждого активного состояния есть кнопка сброса):

- **Период (даты)** — диапазон «с»/«по», + быстрые пресеты: Сегодня, Вчера, Текущая неделя/месяц/квартал/год, Прошлая неделя/месяц/квартал/год, Все время.
- **Тип операции** — выпадающий выбор из четырёх: Все типы / Приход / Расход / Переводы.
- **Счета** — мульти-выбор (можно выбрать несколько). Внутри список с поиском и группировкой (если у счетов есть группы).
- **Статьи** — мульти-выбор. Внутри: сначала спец-элемент «Без статьи», потом обычные категории, сгруппированные по группам категорий.
- **Контрагенты** — мульти-выбор. Внутри: сначала спец-элемент «Без контрагента», потом обычные контрагенты, сгруппированные по группам.
- **Сумма** — диапазон «от»/«до».
- **«Очистить все»** — появляется, только если есть хотя бы один активный фильтр.

### 1.3. Таблица транзакций

Колонки:

| Колонка | Что показывает |
|---|---|
| Чекбокс | Выбор строки для bulk-операций |
| Дата | Дата транзакции |
| Сумма | Сумма со знаком и индикатором направления (приход/расход/перевод) и валютой |
| Статья | Название категории; для перевода — фиксированная подпись «Перевод между счетами»; ниже — описание транзакции (если есть), с автокликабельными URL |
| Контрагент | Название контрагента или прочерк |
| Счёт | Название счёта + подсказка с текущим балансом счёта; для перевода — два счёта (источник и получатель) |

Поведение:

- Сортировка — новые операции сверху (фиксированная, без переключателя).
- Клик по строке открывает форму редактирования.
- Клик по чекбоксу/ссылке внутри строки не должен открывать форму.
- Hover-состояние и состояние «выбранная строка» визуально различимы.
- Если описание содержит URL, ссылки кликабельны и открываются в новой вкладке.

### 1.4. Состояние выбора (bulk-toolbar)

Когда выбрана хотя бы одна строка — на месте обычной шапки таблицы появляется панель массовых действий:

- Счётчик количества выбранных.
- **Копировать** (только если выбрана ровно одна) — открывает форму создания, заполненную данными исходной транзакции.
- **Редактировать** (только если выбраны строки одного типа) — открывает форму редактирования.
- **Удалить** — массовое удаление через диалог подтверждения; видимо только если есть право на удаление.
- Чекбокс «выбрать всё» в шапке имеет три состояния: не выбрано / частично выбрано / всё выбрано.

### 1.5. Пагинация

- Выбор размера страницы: 25 / 50 / 100.
- Текстовый счётчик «X–Y из N».
- Кнопки «предыдущая» / «следующая» страница.
- Индикатор текущей страницы из общего количества.

### 1.6. Состояния экрана

- **Загрузка** — индикатор и поясняющий текст.
- **Нет ни одной операции** — пустое состояние с подсказкой о трёх кнопках создания.
- **Нет счетов / категорий** — отдельное пояснение, что прежде нужно завести базовые сущности.
- **Нет результата по фильтрам** — отдельный текст, не путающий с пустой БД.
- **Активное юрлицо** (необязательная подпись) — короткое уведомление, если применён фильтр по юрлицу из глобального переключателя.

## 2. Боковая панель — форма транзакции (создание / редактирование)

Открывается с правой стороны экрана, фон под ней — затенён, экран остаётся виден.

### 2.1. Заголовок панели

- При редактировании — фиксированный текст «Редактировать операцию».
- При создании — текст «Добавить операцию» + интерактивный элемент с текущим типом операции (приход / расход / перевод). Этот элемент кликабельный — циклически переключает тип. У переключателя три визуально различимых варианта (по одному на каждый тип) с подходящей иконкой.
- Кнопка закрытия панели.

### 2.2. Поля формы для прихода и расхода

- **Сумма** — обязательное; ввод только цифр и десятичной точки/запятой.
- **Счёт** — обязательное; селектор с поиском. Под лейблом — действие «Создать счёт», открывающее форму создания счёта (см. §3.3).
- **Статья** — обязательное; селектор с поиском, отфильтрованный по типу операции (для прихода — только статьи дохода, для расхода — только расхода). Под лейблом — действие «Создать статью» (см. §3.1).
- **Дата** — обязательное; календарный ввод.
- **Контрагент** — необязательное; селектор с поиском. Под лейблом — действие «Создать контрагента» (см. §3.2).
- **Описание** — необязательное; многострочный текст.

### 2.3. Поля формы для перевода

- **Сумма перевода** — обязательное.
- **Счёт списания** — обязательное.
- **Счёт поступления** — обязательное; в селекторе исключается счёт-источник.
- **Дата** — обязательное.
- **Описание** — необязательное.
- (Категория и контрагент не отображаются — для перевода они не имеют смысла.)

### 2.4. Подвал формы

- **Сохранить** — основное действие.
- **Отмена** — закрывает панель.
- **Удалить** (только при редактировании, и только при наличии права на удаление) — открывает диалог подтверждения. Визуально отделено от пары «Сохранить/Отмена», чтобы не нажать случайно.
- Состояние «сохранение в процессе» — индикатор у кнопки «Сохранить», все поля и действия недоступны.

### 2.5. История изменений

Появляется только при редактировании, в нижней части панели.

- Запись «Создано» — дата и время создания, иконка/маркер.
- Запись «Изменено» — дата и время последнего изменения (если отличается от создания).

### 2.6. Защита от потери ввода

Если пользователь сделал хоть одно изменение в форме и пытается её закрыть (крестиком, кликом по затемнению, клавишей Escape) — должен показаться диалог подтверждения с двумя действиями: «Продолжить редактирование» и «Закрыть без сохранения».

### 2.7. Сообщения

- Успех создания/сохранения/удаления — короткое уведомление (toast).
- Ошибка валидации — короткое уведомление с конкретной причиной (сумма ≤ 0, не выбран счёт, совпадают счета перевода и т.д.).
- Ошибка сервера — короткое уведомление с текстом ошибки.

## 3. Боковые панели — inline-создание справочников

Открываются **поверх** уже открытой формы транзакции (вторая панель справа), не закрывая её. После сохранения подсайдбар закрывается, а только что созданная сущность автоматически подставляется в соответствующее поле формы транзакции.

### 3.1. Создание статьи (категории)

Поля:

- **Название** — обязательное.
- **Тип** — выпадающий выбор: Приход / Расход. По умолчанию выбран тип, соответствующий открытой транзакции.
- **Цвет метки** — палитра/цветопикер, плюс действие «Сменить» (генерирует случайный цвет из заранее заданного набора).
- **Описание** — необязательное.

Кнопки: «Создать», «Отмена».

### 3.2. Создание контрагента

Поля:

- **Название** — обязательное.
- **Правовая форма** — выпадающий выбор: ИП / ООО / АО / ПАО / НКО / Прочее.
- **ИНН** — необязательное, цифровой ввод.
- **Телефон** — необязательное.
- **Email** — необязательное.
- **Описание** — необязательное.

Кнопки: «Создать», «Отмена».

### 3.3. Создание счёта

Поля:

- **Название** — обязательное.
- **Юрлицо** — обязательное; выпадающий выбор. По умолчанию — то же, что у выбранного в форме транзакции счёта-источника (если он уже выбран), иначе первое в списке.
- **Тип счёта** — выпадающий выбор: Расчётный / Дебетовая карта / Касса.
- **Валюта** — выпадающий выбор (RUB / USD / EUR).
- **Описание** — необязательное.

Кнопки: «Создать», «Отмена».

(Полные редакторы для всех трёх сущностей доступны в основных разделах CRM — здесь только минимально необходимый набор полей для inline-сценария.)

## 4. Диалоги подтверждения

Все одноуровневые: заголовок, пояснение, два действия.

### 4.1. Удаление одной операции

- Заголовок: «Удалить операцию».
- Пояснение: указание на необратимость.
- Действия: «Отмена», «Удалить» (основное).

### 4.2. Массовое удаление

- Заголовок: «Удалить выбранные операции».
- Пояснение указывает количество удаляемых операций и необратимость.
- Действия: те же.

### 4.3. Закрытие формы с несохранёнными изменениями

- Заголовок: «Закрыть без сохранения?».
- Пояснение: что данные будут потеряны.
- Действия: «Продолжить редактирование», «Закрыть».

## 5. Поп-апы фильтров (детальные)

Каждый фильтр-чип на главном экране открывает свой поп-ап. Везде есть закрытие по клику вне области и по Escape.

### 5.1. Поп-ап «Период (даты)»

- Поля «С даты» и «До даты» — оба календарные.
- Двухмесячный календарь с выбором диапазона.
- Список пресетов (см. §1.2).
- Кнопка «Применить».

При клике по пресету — фильтр применяется немедленно, поп-ап закрывается, кнопка-чип показывает название пресета вместо диапазона дат.

### 5.2. Поп-ап мульти-выбора (Счета / Статьи / Контрагенты)

- Поле поиска внутри.
- Действия «Выбрать все» / «Снять все».
- Список элементов:
  - Спец-элементы («Без статьи» / «Без контрагента») — отдельной верхней секцией без чекбокса группы.
  - Обычные элементы — сгруппированы по группам справочника. У каждой группы — собственный чекбокс с тремя состояниями (всё / часть / ничего); клик по нему выбирает/снимает всю группу.
  - Внутри группы элементы отсортированы по алфавиту (с правильной сортировкой кириллицы).
- Если найденного по поиску ничего нет — текст «Ничего не найдено».
- Изменения применяются мгновенно, без отдельной кнопки «Применить».

### 5.3. Поп-ап «Сумма»

- Два поля: «От» и «До» (числовой ввод).
- Действие «Очистить» (сбрасывает и закрывает поп-ап).
- Действие «Применить» (применяет введённый диапазон и закрывает поп-ап).

В отличие от мульти-выбора и пресетов — изменения здесь применяются только по «Применить», чтобы пользователь не дёргал список после каждой набранной цифры.

## 6. Состояния и реакция на действия

Дизайнеру важно явно проработать визуальную обратную связь для каждого:

- **Hover** строки таблицы, чипа фильтра, кнопки.
- **Focus** для всех интерактивных элементов (важно для клавиатурной навигации и доступности).
- **Loading** у кнопок «Сохранить»/«Удалить» во время асинхронной операции.
- **Disabled**:
  - кнопка «Перевод», если меньше двух счетов;
  - кнопки «Приход»/«Расход», если нет ни одного счёта;
  - кнопки «Удалить» / переключатель «Показать удалённые», если у пользователя нет соответствующих прав (вообще не показывать).
- **Selected row** в таблице — отличается от обычной и от hover.
- **Active filter chip** vs неактивный — должно быть мгновенно различимо.
- **Empty states** — три разных текста (нет данных вовсе / нет счетов или категорий / пустой результат фильтра).

## 7. Что НЕ нужно проектировать (вне скоупа этой страницы)

- Глобальная навигация (сайдбар) — есть, и в ней появляется новый пункт «Транзакции (classic)». Само оформление пункта — в стилистике уже существующих пунктов, ничего нового.
- Шапка приложения и переключатель юрлица — без изменений.
- Полные формы редактирования счёта/категории/контрагента — это отдельные экраны в других разделах CRM.
- Экспорт CSV, soft-delete с переключателем «Показать удалённые» — на legacy-странице их нет.
- Экран деталей транзакции — у legacy-страницы нет отдельного экрана: вся работа с одной транзакцией ведётся в боковой панели.

---

## 8. Подсказки по приоритету

Если объём большой и нужно резать, естественный порядок:

1. Главный экран без панели фильтров (шапка + таблица + пагинация + bulk-toolbar) и форма транзакции в боковой панели — это **MVP**, без этого страница неюзабельна.
2. Панель фильтров и все поп-апы — **критично**, без неё легко разочароваться в первые же 30 секунд.
3. Inline-создание (категория / контрагент / счёт) — **важная фишка**, ради которой и переносим legacy.
4. Защита от потери ввода и история изменений — **полезные хорошести**, можно отгрузить второй итерацией.
