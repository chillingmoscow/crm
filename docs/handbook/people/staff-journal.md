# Журнал и Активность сотрудника

## Что это

В карточке сотрудника (`/people/staff/[id]`) есть **две** вкладки про
аудит:

- **«Журнал»** — события **про этого человека** (что с ним делали:
  принят, переведён, уволен, обновили контакты/медкнижку).
- **«Активность»** — события, которые **этот сотрудник совершил сам**
  (кого принимал/увольнял, какие KB-страницы создавал, какие
  транзакции вносил и т.д.).

Журнал нужен, чтобы причина увольнения и контекст изменений не
терялись со временем. Даже если сотрудника восстановили (и поле
«причина увольнения» в карточке очистилось) — событие остаётся в
журнале с исходной формулировкой.

## Для кого / когда использовать

Доступно владельцу, администратору и бухгалтеру (permission
`org.view_audit`). У управляющего, хостес и официанта вкладки нет.

Полезно когда:

- Сотрудника устраивают второй раз и хочется вспомнить причину
  прошлого ухода.
- Нужно понять, кто и когда сменил его должность, телефон, мед.книжку.
- HR ведёт расследование по неконсистентным данным.

## Что попадает в журнал

| Событие | Что показывает |
|---|---|
| **Принят на работу** | На какую должность приняли, кто принял, когда. |
| **Уволен** | Причина увольнения (обязательное поле в диалоге). |
| **Восстановлен** | Рядом показывается «(ранее уволен DD.MM.YYYY: причина)». |
| **Перевод на другую должность** | `Старая роль → Новая роль`. |
| **Обновление контактов** | Diff «было → стало» по полям: телефон, телеграм, дата рождения. |
| **Обновление HR-данных** | Diff по полям: дата трудоустройства, номер и срок медкнижки, фото паспорта, комментарий HR. |

## Что НЕ попадает

- Смена имени / фамилии / гендера / аватара / адреса — не
  «security-relevant», только засоряло бы.
- Служебные поля (`updated_at`, `created_at`, `active_venue_id`).
- Импорт сотрудников из QuickResto.

## Вкладка «Активность»

Параллельно с «Журналом» в карточке сотрудника есть вкладка
**«Активность»** — это лента событий, где **этот сотрудник был
исполнителем**:

- кого он принимал на работу / увольнял / переводил;
- какие KB-страницы создавал, переименовывал, удалял;
- какие транзакции / счета / контрагенты заводил или редактировал;
- какие настройки заведения / юрлица менял;
- и т.д.

Удобно если хочется понять «что этот сотрудник вообще делал в системе
за последний месяц» — без перехода в общий журнал и фильтрации.

В каждой строке «Активности» дополнительно показывается ссылка на
объект, который сотрудник трогал — клик ведёт на карточку этого
объекта.

## Как пользоваться

1. Открыть карточку сотрудника (Люди → Сотрудники → клик).
2. Перейти на вкладку **«Журнал»** или **«Активность»** (между
   «Документы» и «Опасная зона»).
3. Записи отсортированы от новых к старым.
4. Для событий «обновил данные» под фразой — список изменений
   в формате `поле: было → стало`.
5. Внизу — кнопка **«Показать события старее →»**, если событий
   больше 50. Подгружает следующую страницу без перезагрузки страницы.

## Связь с общим журналом

Эти вкладки — узкий срез общего [Журнала событий](../org/audit.md).
Если нужны события и про этого человека, и про других, и по другим
модулям — открой общий журнал. Там для сотрудника есть **два
независимых фильтра**:

- **«Сотрудник (объект)»** — то же что «Журнал» в карточке: события
  про конкретного человека.
- **«Сотрудник (исполнитель)»** — то же что «Активность»: события
  совершённые конкретным человеком.

Можно комбинировать (AND): например, выбрать «исполнитель = Анна» +
«объект = Петя» → увидеть все действия Анны над Петей.

## Известные ограничения

- Журнал начинается с момента выкатки миграции `153`. События,
  произошедшие раньше, в журнал не попадают.
- Если сотрудник принимался через приглашение по ссылке, событие
  `staff.hired` пишется именно от его имени (он сам себя «принял»
  фактом подтверждения email).
