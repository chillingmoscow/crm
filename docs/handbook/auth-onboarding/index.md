# Авторизация и онбординг

## Что это

Раздел про вход и регистрацию: создание аккаунта владельцем, вход
существующего пользователя, восстановление пароля, принятие
приглашения сотрудником, смена email и сопутствующие письма.

### Какие письма откуда уходят

Письма Sheerly разделены на две группы:

**Через наш SMTP** (Yandex Postbox + nodemailer, брендированный
шаблон):
- Подтверждение смены email (`/auth/confirm-email-change`)
- Alert «Это не я» на старый email при смене
- Письмо-приглашение сотрудника (`/invite/accept?token=...`)

**Через встроенный Supabase Auth email-flow** (стандартные шаблоны
Supabase):
- Письмо подтверждения регистрации (после `/register`)
- Письмо восстановления пароля (после `/forgot-password`)
- Magic-link для апгрейда placeholder-аккаунтов из QuickResto-импорта
  (см. backlog — миграция на custom flow в плане)

Если в продакшене **не настроен наш SMTP** (нет env vars `SMTP_*`
в Coolify) — кастомные письма не уйдут, юзер увидит понятную ошибку.
Supabase Auth письма работают независимо.

## Сценарии входа

### 1. Регистрация владельца аккаунта

1. На странице **`/register`** — email + пароль.
2. Подтверждение по ссылке из письма (`/auth/confirm`).
3. После подтверждения — wizard онбординга (`/onboarding`):
   - Имя, фамилия, контакты;
   - Название аккаунта, тип бизнеса;
   - Первое заведение.
4. Финиш → попадаете в `/dashboard` владельцем своего аккаунта.

### 2. Вход существующего пользователя

1. **`/login`** — email + пароль → попадаете в `/dashboard`.
2. **«Забыли пароль?»** → ссылка на `/forgot-password` → ввод email →
   письмо со ссылкой → форма восстановления пароля
   (`/reset-password`).

### 3. Принятие приглашения от работодателя

Когда руководитель приглашает вас на работу через раздел «Сотрудники»
(см. [people](../people/index.md#приглашение-нового-сотрудника)):

1. На ваш email прилетает письмо **«Вас приглашают в [Заведение]»**
   с кнопкой «Присоединиться».
2. Кнопка ведёт на `/invite/accept?token=...` (нашу страницу, НЕ
   Supabase) — там видно:
   - кто пригласил,
   - в какое заведение/аккаунт,
   - на какую должность.
3. **Если email новый в системе** — форма «Создайте пароль» (придумайте
   пароль с подтверждением). После submit — вы создаётесь как user,
   логинитесь, попадаете в `/profile`.
4. **Если email уже зарегистрирован** в Sheerly (другой работодатель,
   например) — форма «Введите ваш пароль». После submit — вы
   логинитесь под существующим аккаунтом, к нему добавляется новое
   членство в venue. Если пароль забыли — ссылка «Восстановить» рядом.
5. После принятия приглашения — попадаете в `/profile` залогиненный +
   получаете welcome-уведомление в колокольчик с подсказкой заполнить
   профиль (фото, телефон, telegram, ДР).

**Срок действия ссылки — 7 дней.** Если не успели — попросите
работодателя прислать новое приглашение.

### 4. Смена email уже залогиненного пользователя

См. [profile/index.md#смена-email](../profile/index.md#смена-email).

Кратко: вводите новый email → на новый адрес confirm-письмо, на старый
параллельно alert «Кто-то запросил смену, отзовите если не вы». Любая
из ссылок гасит pending-запрос (одна-победившая operation, race-safe).

### 5. Выход

- Меню профиля → **Выйти**.
- Или прямой URL `/auth/sign-out?next=/login`.
- Чистит локальную сессию (cookies) на стороне браузера и редиректит
  на `/login`.

## FAQ / частые ошибки

- **Q:** Перешёл по ссылке из приглашения, увидел странный экран
  Supabase вместо нашего интерфейса.
  **A:** Это был баг до версии с custom invite flow. Сейчас письмо
  ведёт прямо на `/invite/accept` в нашем приложении. Если воспроизвели
  на свежей сборке — пишите в поддержку.

- **Q:** При смене email на новый адрес письмо пришло сразу, но я
  не получил никакого уведомления на старый адрес.
  **A:** На старый прилетает alert-письмо «Это не я — отозвать»
  параллельно с confirm на новый. Best-effort: если SMTP упадёт на
  alert'е, мы не блокируем смену (confirm уже улетел). Проверьте
  спам-папку.

- **Q:** Сменил email, но другая вкладка где я был залогинен под
  старым email — продолжает работать. Это нормально?
  **A:** Временно нормально. Сессии в других вкладках остаются
  валидными до естественного истечения. F5 в той вкладке —
  layout перерендерится с новым email. Полная инвалидация при смене
  email в backlog (issue #266).

- **Q:** Я владелец, но забыл пароль и не получаю письмо на
  восстановление.
  **A:** Письмо восстановления уходит через встроенный Supabase Auth
  SMTP (не через наш nodemailer) — настройка отдельная. Если в Coolify
  / Supabase Studio не сконфигурирован Auth SMTP — связь с админом
  сервера. Проверьте также спам-папку.

## Известные ограничения

- **Только email-pwd**, social login (Google/Apple/etc) не поддерживается.
- **Полная инвалидация сессий при смене email** — в backlog (issue
  #266, P2). Сейчас старые активные сессии продолжают работать.
- **Импорт сотрудников из QuickResto** ещё использует старый
  GoTrue-magic-link flow для апгрейда placeholder-аккаунтов в полноценные
  с email. Перевод на custom flow — в backlog.
- **Public API** для интеграций — нет (см. `BACKLOG.md`).

## Где в коде

- `src/app/(auth)/login` — вход
- `src/app/(auth)/register` — регистрация
- `src/app/(auth)/forgot-password` + `reset-password` — восстановление
- `src/app/(auth)/set-password` — установка пароля по ссылке
- `src/app/(auth)/email-confirmed` — финальный экран подтверждения
- `src/app/(auth)/verify-email` — экран ожидания подтверждения
- `src/app/(onboarding)/onboarding/` — wizard для нового владельца
- `src/app/invite/accept/` — custom invite accept (после `?token=...`)
- `src/app/invite/page.tsx` — legacy multi-tenant accept для уже
  залогиненных юзеров
- `src/app/auth/confirm-email-change/` — подтверждение смены email
- `src/app/auth/revoke-email-change/` — отзыв со старого email
- `src/app/auth/sign-out/` — выход (client-side)
- `src/app/auth/callback/` + `confirm/` — Supabase callback handlers
- `src/lib/people/invitations/mailer.ts` — письма приглашений
- `src/lib/people/email-change/mailer.ts` — письма смены email
- `src/lib/email-templates/` — HTML шаблоны
- `src/lib/mail/transporter.ts` — общий nodemailer-транспорт
- `src/lib/supabase/middleware.ts` — список public paths
- `supabase/migrations/150_invitations_token.sql` — token для invites
- `supabase/migrations/151_lookup_user_id_by_email.sql` — RPC для
  email-conflict guard
