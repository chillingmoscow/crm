# Этап 4: жизненный цикл сотрудника — Telegram-чаты, увольнение, возврат, смена должности

Дата: 2026-11-05. Решения владельца — ответы 5 ноября.

## Зачем

Сотрудников заводят и увольняют в Sheerly, но часть последствий до сих пор делает Glide + n8n или не делает никто:

- из Telegram-чатов при увольнении человека исключал n8n («Удаление сотрудников из чата», последний запуск 30.10 — увольнение через Glide); при приёме приглашения в чаты создавал n8n («Glide / Приглашение в чаты»). В Sheerly этого нет;
- три увольнения от 31.10 застряли: гость в Quick Resto не удалён, потому что на бонусном счёте остаток;
- «Вернуть сотрудника» после полного увольнения в Sheerly запрещено, а n8n восстанавливал записи Quick Resto;
- смена должности меняет только роль доступа, зарплата остаётся на старой должности.

## Решения владельца

1. **Чаты переносим в Sheerly.** Список чатов (сейчас Notion «Чаты»: чекбокс «Приглашения», должности) — в настройки Sheerly. Приём и возврат — одноразовые приглашения в чаты должности; увольнение — исключение из всех чатов с отчётом. Glide-сценарии чатов после этого отключаются.
2. **Бонусы при увольнении — списать и удалить.** Остаток бонусного счёта списывается с записью в журнал, затем гость удаляется. Три застрявших увольнения доводятся так же.
3. **Возврат — как делал n8n:** восстановить прежние записи Quick Resto (сотрудник и гость, тот же PIN). Временно: позже Quick Resto-сотрудников создавать перестанем («один дежурный»).
4. **Смена должности — только зарплата:** должность и модель оплаты в зарплате с датой и историей. Quick Resto и чаты не трогаем.

Файлы и перенос 20 паспортных вложений — отдельный шаг, только по отдельному разрешению владельца; в этот этап не входят.

## Как устроено

### Telegram-чаты

- Бот и чаты организации уже настроены (`organization_telegram_settings`: бот, `default_chat_id` — управленческий чат для отчётов, `candidate_chat_id` — чат для приглашений). Токен — зашифрованный секрет в БД, как сейчас.
- Новая таблица чатов организации: chat_id, название, «приглашать при приёме» (как «Приглашения» в Notion), должности, для которых чат (пусто — для всех с приглашениями); тенантность по CONVENTIONS (account_id, композитные ключи). Наполняется переносом из Notion «Чаты» (одноразово), дальше правится в Sheerly: настройки интеграции Telegram → «Чаты».
- **Приглашение** (приём из кандидатов, возврат): для чатов должности — `createChatInviteLink` с `member_limit=1`, `name` = имя сотрудника; одно сообщение в чат приглашений с кнопками-ссылками, как делал n8n. Защита от двойного запуска по ключу (сотрудник, событие).
- **Исключение** (увольнение): по всем чатам организации `getChatMember`; если состоит — `banChatMember` + `unbanChatMember(only_if_banned)`; «уже нет» — только left/kicked/restricted без членства; «member not found» и ошибки API — «не подтверждено». Нужен Telegram ID сотрудника (`profiles.telegram_id`); если его нет — шаг «не подтверждено», без молчаливого успеха.
- Каждое действие — запись в журнал попыток с итогом по чату («исключён», «уже нет», «ошибка», «не подтверждено»); отчёт в управленческий чат. Увольнение не считается завершённым, пока по всем чатам нет подтверждённого итога; повтор — та же кнопка «Повторить» / автоматический повтор.

### Увольнение

- Шаг Quick Resto перед удалением гостя: если на бонусном счёте остаток — списание остатка (тем же клиентом бонусов, что и премии/штрафы) с записью в журнал увольнения (сумма, момент), затем закрытие счёта и удаление гостя. Повтор безопасен: перед списанием перечитывается баланс.
- Шаг Telegram — см. выше.
- Повторы: добавить cron, который подхватывает `staff_terminations` в `error`/`working` по `available_at` (сейчас только ручной повтор).
- Три застрявших увольнения 31.10 доводятся новым кодом (повтор).

### Возврат («Вернуть сотрудника»)

- Для полностью уволенного (Quick Resto удалён): восстановить в Quick Resto сотрудника и гостя (`recover`), вернуть группу Staff, прежний PIN; бонусный счёт — заново (прежний закрыт); код двери — новый из пула (как при приёме); `payroll_employees.active = true`; статус доступа — active; приглашения в чаты должности.
- Как увольнение: журнал шагов, идемпотентность, повтор.
- Если запись в Quick Resto восстановить нельзя (стёрта) — ошибка с понятным текстом, без частичного «успеха».

### Смена должности

- Смена должности сотрудника с датой «с»: роль доступа + `payroll_employees.role_id/role_name/model_id` + запись в истории моделей (`payroll_employee_models`) с этой датой. Прошлые начисления не пересчитываются; дни с даты — пересчитываются (очередь зарплаты).

## Не цели

- Создание Quick Resto-сотрудников по-новому («один дежурный») — позже.
- Изменение должности в Quick Resto и перевыдача чатов при смене должности.
- Перенос паспортных файлов (отдельное разрешение).
- Приём «Добавление на смену» и «Подсказка по онбордингу»: зарплата считается в Sheerly; подсказку — в справку.

## Приёмка

На реальном сотруднике-тесте или ближайшем реальном событии: приём → приглашения пришли; увольнение → исключён из чатов, бонусы списаны, гость удалён, отчёт; возврат → Quick Resto восстановлен, приглашения; смена должности → зарплата с даты. Затем выключить в n8n: «Glide / Увольнение сотрудника», «Удаление сотрудников из чата», «Glide / Приглашение в чаты», «Сотрудники / Восстановление», «Сотрудники / Изменение должности», «Сотрудники / Добавление на смену», «Сотрудники / Подсказка по онбордингу» — только по команде владельца.

## Оставлено исполнителю

Раскладка UI настроек чатов (по `docs/design-system.md`), формат отчётов в чат, имя таблиц/RPC, точный интервал повторов.
