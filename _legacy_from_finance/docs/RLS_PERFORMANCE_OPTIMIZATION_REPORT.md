## 📊 Проблемы, которые были решены

### 1. Auth RLS Initialization Plan (29 предупреждений)
**Проблема:** Функция `auth.uid()` вызывалась для каждой строки в запросе  
**Пример:** При запросе 1000 строк функция выполнялась 1000 раз вместо 1 раза  
**Решение:** Заменили `auth.uid()` на `(SELECT auth.uid())` во всех политиках

### 2. Multiple Permissive Policies (64 предупреждения)
**Проблема:** Несколько разрешающих политик для одного действия (SELECT)  
**Пример:** Для таблицы `organizations` было 5 политик SELECT вместо 1  
**Решение:** Объединили все политики в одну унифицированную для каждой таблицы

### 3. Duplicate Index (3 предупреждения)
**Проблема:** Дублирующиеся индексы замедляли операции INSERT/UPDATE  
**Решение:** Удалили старые индексы, оставили оптимизированные новые

## 🔧 Выполненные изменения

### Миграция `20250607000004_fix_rls_performance_issues.sql`

**Удаленные дублирующиеся индексы:**
```sql
DROP INDEX IF EXISTS idx_legal_entities_org;
DROP INDEX IF EXISTS idx_organizations_owner;  
DROP INDEX IF EXISTS idx_positions_org;
```

- `positions_access` - унифицированный доступ к должностям
- `position_permissions_access` - унифицированный доступ к правам должностей
- `user_assignments_access` - унифицированный доступ к назначениям
- `accounts_access` - унифицированный доступ к счетам
- `categories_access` - унифицированный доступ к категориям
- `counterparties_access` - унифицированный доступ к контрагентам
- `transactions_access` - унифицированный доступ к транзакциям
- `account_groups_access` - унифицированный доступ к группам счетов
- `category_groups_access` - унифицированный доступ к группам категорий
- `counterparty_groups_access` - унифицированный доступ к группам контрагентов

**Ключевая оптимизация:**
```sql

```
