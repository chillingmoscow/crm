# Полные инструкции задач Notion → KB

Перенос выполняется отдельно от включения задач. Производственная база, n8n, зарплата и сообщения этим этапом не переключаются.

## Подготовленный локальный объём

- Все 41 исходный шаблон календаря, включая неактивные и пустой `New page`.
- 42 выключенные задачи после разделения подсвечников. У 15 подготовлены чек-листы; у остальных 27 повтор и чек-лист не назначаются автоматически. Суммы и исходные идентификаторы сохраняются.
- 30 явно связанных руководств; 56 уникальных изображений и PDF. Изображения внутри списков также переносятся. Повторяющиеся файлы объединяются по SHA-256.
- 51 дальнейшая ссылка представлена страницей «Материал ещё не перенесён», без копирования содержимого. Требуется решение владельца о персональных карточках, ассортименте и складских данных, на которые ведёт цепочка ссылок.
- Одна старая статья о посудомоечной машине недоступна в Notion (404). Она явно отмечена; замена её содержания пока не согласована.

В базе знаний сохраняется полный форматированный текст, таблицы, изображения и вложения. Два самостоятельных этапа подсвечников сохраняют свои подготовленные инструкции; исходная объединённая статья находится в связанных материалах. В тексте задач учтены понедельник для уборки за холодильниками и непрерывный цикл четырёх групп холодильников.

## Частный пакет

Не коммитить исходные MCP-ответы: `metadata.references`, свойства файлов и иконки могут содержать временные ключи скачивания. Не коммитить весь связанный граф: в нём обнаружены персональные и операционные записи. При изменении объёма сначала получить решение владельца.

Подготовка из уже полученных ответов и проверенных файлов:

```sh
# BeautifulSoup 4.13.4, mistune 3.1.3 — отдельное окружение Python.
python scripts/prepare-notion-task-bundle.py CACHE_DIR OUTPUT_DIR APPROVED_SOURCE_IDS.json
```

`APPROVED_SOURCE_IDS.json` — массив идентификаторов согласованных руководств. Все 41 исходный шаблон включаются дополнительно автоматически. Без этого файла обрабатывается весь кеш; использовать такой режим только для согласованного объёма. Пакет содержит `bundle.json`, файлы по хешам, отметки недоступных источников и предупреждения о пропусках. Временные URL в него не включаются. Проверить `missingAssets`, `warnings`, `pendingPages` до применения; наличие страницы-заглушки не означает переноса её содержимого.

## Применение

Сначала применить миграции PR и выполнить исходные `import-notion-tasks.mjs` и `migrate-task-instructions.mjs` для 15 подготовленных задач. Затем:

```sh
node scripts/import-notion-task-bundle.mjs --venue UUID --bundle OUTPUT_DIR
node scripts/import-notion-task-bundle.mjs --venue UUID --bundle OUTPUT_DIR --apply
node scripts/import-notion-task-bundle.mjs --venue UUID --bundle OUTPUT_DIR --verify
```

По умолчанию первая команда только сверяет пакет. `--catalog-only` добавляет исключительно недостающие выключенные шаблоны, без переноса KB. В production для записи дополнительно нужны `--allow-production` и `TASK_INSTRUCTION_ACCESS_TOKEN` владельца. Активный аккаунт и заведение проверяются; локальные seed-реквизиты допускаются только для localhost. Перенос останавливается при включённых задачах, назначениях или ранее включённой обработке.

Страницы создаются и сохраняются через обычный доступ владельца, версии KB и аудит. Файлы загружаются в закрытый `account-attachments` и штатно регистрируются. Задачи связываются со страницами через `schedule_task_command`, с проверкой версии и прав. Сторонние ручные изменения текста сохраняются; недостающие изображения добавляются. Ключи и файлы проверяются до записи, путь вложения ограничен каталогом пакета. Повторный запуск не создаёт дубли.

`state-UUID.json` хранит хеши импортированного содержимого для продолжения и обновления без перезаписи ручных правок; сохранять его вместе с пакетом. `--verify` читает все файлы под обычными правами владельца и проверяет их байты по SHA-256. Снимки инструкций и доступ сотрудников продолжают использовать штатную изоляцию заданий.
