# Допродажи

В «Продажи → Допродажи» два раздела: **Бар** и **Кальяны**. Выберите месяц и источник.
В таблице — рабочие дни, выручка, себестоимость и общая прибавка; у мастеров также
баллы. Количество по каждой категории можно включить через «Столбцы» или посмотреть
в карточке дня. График показывает среднее количество по дням с известным значением.
Прочерк не заменяется нулём. Неполные месячные итоги показывают охват завершённых дней.

**Архив Glide** хранит прежние значения Fees → Sales/KPI без пересчёта. Нажатие даты
открывает карточку; «История» содержит время снимка и ссылки на строки источника.
Повторный импорт того же снимка не создаёт дублей. Изменённый источник сохраняется
новым снимком, старый остаётся в базе. Доход мастеров пока не рассчитывается.

**Sheerly** получает отчёты непосредственно из Quick Resto. Обновление запрашивает
завершённые дни выбранного месяца, для которых заданы правила. Дальше работает
фоновый обработчик; окно браузера можно закрыть. Автоматически проверяются три
последних завершённых дня. Рабочее окно едино с продажами — с 09:00 по Москве
в CHILLING. При ошибке показываются последние сохранённые значения с состоянием
обновления. Карточка сохраняет правила именно этих значений, а не нового запроса.
«История» содержит предыдущие получения отчёта и общую прибавку.

Прибавка бара: количество в категории × её ставка. У мастеров продажи дают баллы;
оплачивается целое число баллов по ставке достигнутого порога. Общий фонд делится
в расчёте зарплаты между сотрудниками соответствующего направления за рабочий день.
Отчёт конструктора дополняет выручку и себестоимость бара; его количество повторно
не начисляется. Вложенные товарные строки не удваивают итоги отчётов.

В «Правилах расчёта» можно менять ставки, категории Quick Resto, веса баллов и шкалу.
Изменение сохраняется новой версией с датой начала и причиной, со следующего рабочего
дня. Прошлые начисления не пересчитываются. Одновременное изменение другим пользователем
потребует перечитать настройки. Изменения правил и запросы отчётов видны в журнале событий.

Просмотр требует доступа к сменам продаж, обновление — права обновления, правила —
права настройки, CSV — права экспорта. Права повторно проверяются на сервере.
Экспорт сохраняет видимые колонки, источник, состояние, дату получения и ссылки на архив.

Чтение отчётов и импорт архива не проводят выплат, премий, расходов и списаний бонусов.
На время проверки n8n продолжает работу; реальный бонусный обработчик остаётся один.
