# Проверка переноса задач

Подготовлена локальная реализация повторяющихся задач для продолжения после PR #599. На производственной базе она не включалась, состояния сценариев n8n не менялись.

## Подготовленные данные

- Прочитано 41 описание шаблона Notion и проверены 14 включённых повторов в интерфейсе.
- После разделения подсвечников подготовлено 15 выключенных черновиков: 58 отметок, 19 обязательных фотографий и один текстовый отчёт.
- Приёмка по умолчанию управляющим; у каждой задачи можно выбрать автоприёмку.
- Подготовка подсвечников без начислений. У финальной мойки сохраняются 300 ₽ штрафа и 300 бонусов за выполнение после переноса.
- Холодильники обслуживаются непрерывным циклом из четырёх групп. Уборка за холодильниками назначается в понедельник.
- Локальный повтор импорта находит 15 существующих задач и не создаёт новых. Включение обработчика импортом не выполняется.

## Выполненные проверки

- [x] TypeScript и полный lint проекта.
- [x] Существующие проверки бонусного исполнителя, правил зарплатных автоматизаций, состояния автоматизаций и импорта прежних начислений.
- [x] SQL-сценарий с полным откатом: предпросмотр без записей, защита до перехода, назначение по опубликованной смене, обязательное фото, запрет чужого фото, ожидание управляющего без штрафа, запрет самоприёмки.
- [x] SQL-сценарий: отсутствие обычной премии, единственный штраф и перенос при повторе, блокировка при отменённой смене, автоприёмка и единственная премия за перенос через существующую бонусную очередь.
- [x] SQL-сценарий: повторные переносы сохраняют исходную подготовку и оборудование; неоднозначное назначение после начала отчёта задерживает начисление и восстанавливается после исправления графика.
- [x] Удаление будущей смены через действующую команду календаря отделяет назначение с аудитом; новая опубликованная смена подхватывается обработчиком. Поздняя приёмка подготовки оставляет зависимую просроченную задачу на сверке без штрафа и переноса.
- [x] Замена сотрудника после срока через действующую команду назначения не переносит штраф на нового ответственного.
- [x] Реальный HTTP-экран включает связанный завершённый отчёт 46-дневной давности для возвращённого отчёта за пределами месячного окна. Временные записи удалены.
- [x] Поздняя публикация обычной смены после срока задачи оставляет назначение на сверке без автоматического штрафа; проверено через действующую команду публикации.
- [x] Пропущенный продлённый срок исправления создаёт перенос на текущий доступный день; повторные запуски не создают задания задним числом и цепочку штрафов другим сменам.
- [x] Поздняя приёмка сохраняет премию; возврат требует нового будущего срока, не вызывает немедленный штраф и позволяет пересдать старый отчёт. Непроверенные отчёты доступны за все дни.
- [x] Неопределённая отправка остаётся на сверке. Проверены реальные форматы HTTP-ответов Telegram: подтверждение, явный отказ, повреждённый JSON, отсутствие номера сообщения и противоречивые ответы.
- [x] Проверка от роли `authenticated`: сотрудник видит свой отчёт, чужой отчёт и его фотография скрыты; следующий ответственный получает доступ только к связанному предыдущему отчёту и фото.
- [x] Реальная локальная загрузка PNG в закрытый bucket, сдача отчёта, чтение по подписанной ссылке, отказ в чужой загрузке и анонимном чтении. Временные данные и файл удалены.
- [x] HTTP-загрузка `/schedule/tasks` под тестовым владельцем: 200, новый экран и импортированные инструкции доступны.
- [x] Supabase security advisors: замечаний к объектам задач нет. Отдельное предупреждение относится к не изменяемой функции `private.my_visible_file_ids`.
- [x] В браузере: вход тестового владельца, переход из меню к задачам, список черновиков и редактор финальной мойки подсвечников.
- [x] Мобильная форма при ширине 390 px: пункты, отметки и перенос кнопок доступны без горизонтальной прокрутки.
- [ ] Завершение мобильного отчёта с фото: расширение браузера требует «Allow access to file URLs». Реальная загрузка и сдача ранее проверены через локальные API; браузерная проверка ожидает настройки или ручного выбора.
- [x] Тексты инструкций направляют отчёт в Sheerly; подготовка и мойка подсвечников содержат отдельные действия. Исходные тексты сохранены в архиве Notion.

## Условия переключения

1. Влить код и применить миграцию `318_schedule_recurring_tasks.sql` до выпуска приложения. Миграция содержит `begin/commit`; внешний `psql -1` не использовать.
2. На рабочем заведении выполнить сухой импорт, проверить точные соответствия шаблонов и только затем создать черновики. Существующие записи при повторе не перезаписываются.
3. Проверить пункты, фотографии, приёмку и расписание. Текст инструкций уже переносится в Sheerly; иллюстрации пока доступны по исходным ссылкам Notion. Внешняя картинка в заточке ножей возвращает 404 и в самом источнике.
4. Сверить результаты переходного периода в Fees с журналом Sheerly. Новый код не читает Fees и сам не восстанавливает пропущенные прежние начисления.
5. Выключить старые ветки планирования задач, разбора результатов и напоминаний. В смешанном сценарии отдельно сохранить праздники: этот PR не переносит календарь праздников и VIP-напоминания.
6. Выбрать дату перехода и чаты в настройках задач. Общая политика бонусов и `PAYROLL_BONUS_WRITES_ENABLED` остаются дополнительными действующими ограничениями.
7. Проверить реальный рабочий день с повторным чтением назначений, начисления и сообщения. До этого включение на производственной базе не считается принятым.
