# Пересорт в акте инвентаризации

## Что это

**Пересорт** — операция в акте инвентаризации, когда недостача одной
позиции считается «равной» излишку другой. Чаще всего это случай когда
бармен/повар перепутал две похожие позиции (например, два виски или два
вида молока): по факту суммарно ничего не пропало, просто учётка
показывала их разделёнными.

## Как сделать пересорт

1. Открой акт → вкладка «Итоги».
2. Выдели две (или больше) позиции, у одних должна быть недостача,
   у других — излишек.
3. Все позиции должны быть **из одной группы** и **в одной единице
   измерения**. Виски в литрах нельзя пересортить с виски в штуках,
   и колу нельзя пересортить с виски (разные группы).
4. Нажми «Создать пересорт» → укажи причину (по умолчанию «Ручной
   пересорт») → подтверди.

## Что произойдёт в управленческом учёте

Алгоритм уравнивает позиции **по объёму**: берёт минимум недостачи и
излишка. Объёмная часть, которую покрыли пересортом, обнуляется
в «управленческих итогах».

### Корректировка себестоимости (с миграции 205)

**Что это.** Если две позиции в пересорте имеют разную себестоимость,
объём уравнялся, но **деньги** — нет. Это реальный убыток компании,
который раньше терялся.

**Пример.**
- Виски A (премиум 5 000 ₽/л) — недостача 1 л = −5 000 ₽
- Виски B (базовый 3 000 ₽/л) — излишек 1 л = +3 000 ₽
- Пересорт уравнял по объёму (1 л на 1 л).
- **Реальная потеря компании = 5 000 − 3 000 = 2 000 ₽** —
  списали дорогое, нашли дешёвое. Этой суммы реально нет на складе.

**Как считаем.** Для каждого пересорта:
```
shortageCostPerUnit = сумма_недостач / объём_недостач   (взвешенная средняя)
surplusCostPerUnit  = сумма_излишков / объём_излишков
costAdjustmentSum   = max(0, (shortageCostPerUnit - surplusCostPerUnit) × offsetAmount)
```
**Признаётся только убыток (≥ 0).** Если излишек оказался дороже
недостачи (т.е. потенциальная «прибыль») — корректировка обнуляется.
Это управленческий консерватизм: «прибыль» в инвентаризации обычно
означает ошибку учёта, не реальный доход, и её недостоверно признавать.

**Где видно.**
- В карточке активного пересорта на вкладке «Итоги» появляется
  строка `Корректировка себестоимости: −X ₽` (розовая, если > 0).
- В управленческой сводке `managementShortfallSum` — корректировка
  плюсуется к недостаче.

**Multi-pair случай.** Если в одном пересорте 2+ недостач и 2+ излишков
с разной себестоимостью — считаем взвешенные средние по сторонам,
формула та же.

## Что НЕ делает пересорт

- **Не меняет QR-данные.** Оригинальные `shortfall_sum` / `surplus_sum`
  документа остаются на месте, отчётность по QR не искажается.
- **Не списывает физически.** Сами позиции в `document_items` остаются
  как были — пересорт это **управленческое представление** разниц.
- **Не отменяет себя автоматически.** Если ошибся — есть кнопка
  «Отменить» с указанием причины (status = voided).

## Карточка ингредиента из «Итогов»

Клик по **названию позиции** в таблице «Итоги» открывает боковую панель с
обзором ингредиента: фото, группа, единица измерения, артикул, штрих-код,
себестоимость, остаток и описание. Из панели можно перейти на полную
карточку («Открыть карточку»). Панель только для позиций, привязанных к
ингредиенту каталога.

## Подсказки пересорта

На странице «Итоги» система предлагает кандидатов на пересорт:

- **По истории** — показываются автоматически: если похожий пересорт уже делали в прошлых актах (те же ингредиенты с противоположными расхождениями).
- **ИИ** — по **синей иконке с волшебной палочкой** в ряду кнопок над таблицей итогов (если ИИ включён в аккаунте и есть право). При наведении — подсказка «Подсказки пересорта (ИИ)». Грузится по запросу, чтобы не замедлять открытие акта; анализирует названия и расхождения в пределах одной группы и единицы измерения.

Подсказку можно **«Применить»** (создаёт пересорт) или **«Скрыть»** (не показывать в этом акте). Доступны, только пока итоги можно менять.
