# Перенос зарплаты и графика на сервер

Релиз включает новый общий интерфейс, график, финансовые смены, настройки оплаты должности, начисления и выплаты. Текущая схема до релиза заканчивалась миграцией 240. Новые миграции имеют линейные номера **241–256**: график → продажи → ограничение запросов → базовая зарплата → её дополнения. Timestamp-имена первоначальных локальных файлов заменены до финального выпуска; смешанный порядок не подходит для чистой установки.

Перед переносом сохраняются полный дамп рабочей базы и контрольная сумма. Восстановление и все новые миграции проверяются в отдельных базах на том же сервере. Дамп не скачивается на рабочий компьютер. При проверке восстановления без владельцев/прав допустим только известный конфликт уже созданного представления vault.decrypted_secrets; ошибки объектов приложения недопустимы.

Уже применённые до переименования версии учитываются только в реестре миграций: сопоставление 16 старых имён с 241–256 выполняется транзакционно, без повторного выполнения SQL и без удаления таблиц. Резервная копия реестра входит в полный дамп. Для новой установки используются только конечные имена файлов репозитория.

## Данные

Адресный перенос выполняется в существующий CHILLING MOSCOW. Аккаунт, заведение, должности и сотрудники сопоставляются с серверными идентификаторами; вся локальная база целиком не восстанавливается поверх рабочей.

Согласованный пакет: 295 опубликованных смен, 47 зарплатных карточек, 226 начислений, 46 записей начислений/удержаний, датированные условия и история. Суммы исходного снимка сверяются до и после. Назире сохранены 160 400 ₽ за сентябрь и отдельные исторические доплаты. Фактические списания бонусов не выполняются.

Локальные платежи, их распределения, кассовые выдачи, таблица неподтверждённых прежних выплат, проверочные банковские счета и юрлицо исключены. Начальные остатки на сервере требуют проверки: локальное подтверждение нулей для проверки интерфейса не является доказательством реального долга. Прежние выплаты и оставшиеся расхождения Glide сверяются отдельно.

Используются существующие карточки сотрудников и внешние связи Quick Resto. Три отсутствующие штатные карточки создаются без пароля и приглашения, с бессрочно заблокированным входом. Разовые сотрудники остаются без аккаунтов. Перенос не добавляет разрешения существующим сотрудникам. Исторические локальные авторы не подменяются серверным владельцем: сохраняется происхождение записей; отдельное событие переноса фиксирует автора самого импорта.

Обработчики запускаются серверным планировщиком через защищённые /api/cron/payroll и /api/cron/sales-shifts; секрет берётся только из окружения приложения. Одновременные запуски ограничиваются блокировкой. После обновления проверяются точный commit образа, health, вход, доступ к страницам и выполнение очереди. Рабочий dev-сервер сохраняется для дальнейших доработок.
