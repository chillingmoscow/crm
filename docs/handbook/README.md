# Handbook — справка по приложению Sheerly CRM

Эта папка — **источник правды** для пользовательской документации (обучалки) по каждому функциональному блоку приложения.

## Что это и чем НЕ является

**Handbook — это:**
- Объяснения для конечного пользователя: что делает каждый модуль, как им пользоваться, какие есть ограничения.
- Markdown-файлы в репо рядом с кодом. Обновляются вместе с фичами.

**Handbook — это НЕ:**
- Внутренняя KB-фича в приложении (`/knowledge` route, `src/app/(dashboard)/knowledge/`). Та фича — для пользователей, чтобы они создавали **свои** статьи в **своём** аккаунте. Здесь же — справка про **само приложение**.
- Техническая документация для разработчиков. Для неё — соседние файлы в `docs/` (`design-system.md`, `CURRENT_TENANCY.md`, `auth-design-guide.md`, и т.д.).
- ADR / решения по архитектуре. Их место — в `docs/` верхнего уровня.

## Текущий статус публикации

Пока handbook **не отображается пользователям** — это markdown в репо. Когда контента наберётся (≥10 заполненных страниц), отдельным PR'ом подключим `next-mdx-remote` и роут `/help`. См. соответствующий пункт в `BACKLOG.md`.

## Структура

Одна папка на каждый функциональный модуль из `src/app/(dashboard)/` (+ `auth-onboarding` объединяет `(auth)` и `(onboarding)`):

| Раздел | Что внутри |
|---|---|
| [`crm/`](./crm/index.md) | CRM: клиенты, карточки, взаимодействия |
| [`knowledge/`](./knowledge/index.md) | Внутренняя база знаний пользователя (BlockNote-страницы) |
| [`finance/`](./finance/index.md) | Финансы: счета, категории, контрагенты, транзакции |
| [`notifications/`](./notifications/index.md) | Уведомления |
| [`people/`](./people/index.md) | Сотрудники |
| [`org/`](./org/index.md) | Оргструктура |
| [`settings/`](./settings/index.md) | Настройки (интеграции и т.д.) |
| [`dashboard/`](./dashboard/index.md) | Главная |
| [`profile/`](./profile/index.md) | Профиль пользователя |
| [`auth-onboarding/`](./auth-onboarding/index.md) | Авторизация и онбординг |
| [`support/`](./support/index.md) | Помощь и поддержка (форма обратной связи) |

Внутри каждой папки — как минимум `index.md` (обзор раздела). По мере роста добавляются страницы под конкретные фичи: `crm/contact-card.md`, `finance/transactions.md` и т.д.

## Шаблон страницы

Используй [`_template.md`](./_template.md) при создании любой новой страницы.

Каждая страница содержит секции:
1. **Что это** — одно предложение.
2. **Для кого / когда использовать** — пользовательские сценарии.
3. **Как пользоваться** — пошаговая инструкция.
4. **FAQ / частые ошибки** — реальные вопросы и грабли.
5. **Известные ограничения** — что не работает / не поддерживается.
6. **Где в коде** — пути в `src/` (для будущих доработок и для AI).

## Правила дописывания

- **Любой PR с user-visible изменением** обязан обновлять/добавлять соответствующую страницу в `docs/handbook/<module>/`. Это закреплено в корневом `CLAUDE.md`.
- Пиши с точки зрения пользователя, а не разработчика. Не пиши «вызывается server action `createTransaction`» — пиши «нажмите *Добавить операцию*».
- Не выдумывай. Если фича ещё не сделана — секция остаётся `_TBD_`.
- Не дублируй design-system.md / auth-design-guide.md / dev-руководства. Если нужно что-то техническое — ссылайся.

## Граница с внутренней KB-фичей

В приложении уже есть раздел **Knowledge** (`/knowledge`), где пользователь сам создаёт свои статьи через BlockNote-редактор. Это **пользовательский контент в БД**, а не справка по приложению.

- Справка по тому, **как пользоваться** этой Knowledge-фичей → `docs/handbook/knowledge/index.md` (этот файл).
- То, что пользователь **пишет внутри** Knowledge-фичи → лежит в Supabase, не в репо, не имеет отношения к handbook.
