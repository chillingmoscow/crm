# Акты инвентаризации — список

Страница **Документы → Акты инвентаризации**.

## Что это

Список всех актов инвентаризации текущего аккаунта, доступных вашему уровню
доступа. Рядом с заголовком — число актов; когда выбраны фильтры или поиск,
оно показывается как «N из M» (найдено из всех). Используется ежедневно: смена начинает счёт, менеджер раздаёт
задачи, владелец смотрит итоги и пересорт. По умолчанию акты отсортированы по
дате — новые сверху; сортировку и фильтры можно менять (см. ниже).

## Фильтры

Кнопка фильтров в шапке раскрывает ряд условий под ней. Ряд по умолчанию
свёрнут; выбранный фильтр виден всегда, даже когда ряд свёрнут. Кнопка
подсвечивается, только когда выбран хотя бы один фильтр. Активные чипы
подсвечены синим, у каждого есть крестик для сброса.

- **Заведение** — конкретное заведение. Чип показывается, только если
  заведений больше одного. Пользователь видит только заведения своего
  членства. Право `inventory.view_all_venues` расширяет список до всех
  заведений аккаунта.
- **Статус** — мульти-выбор (Новый / Назначен / В работе / Готов к проверке /
  На пересчёте / Итоги требуют проверки / Проведен).
  Последний — служебный, на случай сбоя загрузки из Quick Resto; сейчас акты в
  него не попадают, и фильтр по нему всегда пуст.
- **Исполнитель** — Любой / На меня / Без назначения / конкретный
  сотрудник. Фильтр виден тем, у кого есть право управлять актами; линейный
  сотрудник его не видит — он и так видит только свои назначения.
- **Проверяющий** — Любой / Проверяю я / Без проверяющего / конкретный
  сотрудник. Тоже для управляющих актами; помогает найти «что ждёт моей
  проверки».
- **Склад** — мульти-выбор по складам, доступным пользователю (в длинном
  списке есть поиск).
- **Пересчёты** — «Только пересчёты» или «Без пересчётов».
- **Период** — пресеты «Весь архив (по-умолчанию)», «7 дней», «30 дней»,
  «90 дней», «Свой диапазон» (два датапикера). По-умолчанию фильтр периода
  отсутствует — видны все акты, новые сверху.

Кнопка **«Очистить все»** справа от фильтров сбрасывает их разом, включая
поиск и сортировку.

## Сортировка

Кнопка сортировки в шапке — список полей (Дата, Номер, Статус). Можно
сортировать по нескольким полям сразу: выбранные появляются одним чипом в
ряду условий («Дата» со стрелкой или «2 сортировки»), там же меняется
направление и порядок. Клик по заголовку столбца: по возрастанию → по
убыванию → без сортировки. Без выбранной сортировки акты идут по дате, новые
сверху.

**Группы по дате.** Пока список отсортирован по дате (так по умолчанию), акты
одной инвентаризации — одна дата, разные склады и группы — собраны под общим
подзаголовком: «Понедельник, 23 ноября · 4 акта · итог −1 335,0 ₽ · Бар,
Кухня». Итог — сумма итогов актов этой даты на текущей странице (излишки минус
недостачи); акты, у которых итогов ещё нет, в неё не входят: тогда рядом с итогом
серым стоит «(3 из 4)» — сколько актов посчитано. Дата акта считается в
часовом поясе его заведения, как в карточке акта: акт, начатый в 01:30, стоит
в своём дне, а не в предыдущем. Если дата попала на границу страниц, итог
каждой страницы — по её актам. При сортировке по номеру или статусу групп нет:
акты одной даты там разбросаны по списку. Фильтры, поиск, выделение и сумма
итогов по выделению работают как прежде; на телефоне подзаголовок стоит над
карточками своей даты.

## Справка и горячие клавиши

Кнопка **«?»** в верхней панели (слева от колокольчика уведомлений) на всех
страницах акта открывает боковую панель со справкой: роли, статусы,
уведомления.

Клавиша **`?`** открывает шпаргалку горячих клавиш. Она контекстная —
показывает глобальные клавиши и клавиши текущего раздела. Для списка актов:

- `J` / `K` — следующая / предыдущая строка (выделение).
- `Enter` — открыть выделенный акт.
- `/` — поиск.
- `F` — показать / скрыть фильтры.

Клавиши не срабатывают, пока курсор в поле ввода.

## Массовые действия и сумма итогов

Менеджер может выделить несколько актов чекбоксами (или «выбрать все» в шапке
таблицы). В появившейся нижней панели:

- **Сумма итогов по выделению** — нетто-расхождение (излишки минус недостачи)
  по выбранным актам одним числом: плюс зелёным, минус красным. Удобно быстро
  прикинуть итог по нескольким актам (например, выставить размер страницы 100,
  «выбрать все» и посмотреть сумму). Выделять можно **любые** акты, включая
  проведённые.

  Это **управленческий итог** — тот же, что в колонке «Итоги» и в карточке акта:
  считается по строкам, с учётом исключённых позиций и сведённых пересортов.
  Он доступен сразу, как только акт сдан, а не после проведения. У актов, по
  которым подсчёт ещё не завершён, вклад нулевой — итогов у них пока нет.
  Если хотя бы по одному выделенному акту итог посчитать не удалось, вместо
  суммы показывается прочерк: частичной суммы не бывает.
- **Исполнитель / Проверяющий** (назначить) и **Удалить** — доступны только
  когда **все** выделенные акты подходят. Для «Удалить» это значит: акт не
  проведён, у него нет утверждённых итогов и он не создаётся (проведённый
  удаляют по одному — с отменой проведения). Если в выборке есть хотя бы один
  такой акт, этих кнопок нет — остаётся только счётчик и сумма (чтобы не было частичного применения:
  «выделил 2 — удалился 1»). В меню назначения — сотрудники, у которых есть
  право на эту роль хотя бы в одном из заведений выбранных актов; акты, где
  права нет или человек уже стоит на второй роли, пропускаются и попадают в
  «пропущено». Назначенному приходит одно сводное уведомление, по каждому
  акту пишется запись в журнал.

Сумма считается по выделенным строкам **текущей страницы**.

## Поиск

Иконка лупы в шапке открывает поле. Минимум — 2 символа, дебаунс 250мс.

Что ищется:

- **№ акта** — частичное совпадение.
- **Комментарий к акту** — частичное совпадение.
- **Названия ингредиентов в позициях акта** — частичное совпадение по
  `document_items.product_name`.

Если совпадение нашлось в позициях, в строке акта появляется чип
«🔍 Coca-Cola» (до трёх совпадений) — чтобы было понятно, _почему_ именно
этот акт попал в результаты.

## Live-обновления

Список обновляется в реальном времени без F5. Если коллега назначил вам
акт или закончил счёт — вы увидите изменение в течение секунды. Это
работает на уровне всех актов вашего аккаунта.

## Табы акта

Открытый акт — карточка: сверху «Акт № …», под ним склад, дата акта и
статус. Путь в верхней панели — «Документы / Акты инвентаризации / Акт № …»:
по второму звену можно вернуться к списку. Ниже вкладки: **Основное · Форма ·
Итоги · Журнал · Опасная зона** (часть видна по правам).

- **Опасная зона** показывается, только когда акт можно удалить (у вас есть
  право управлять актами и итоги не утверждены). См. ниже
  «Удаление акта».
- **Журнал** — события по акту в том же виде, что журнал сотрудника или
  должности: по дням («Сегодня», «Вчера», «16 ноября»), кто и что сделал, по
  каким позициям и с какой причиной; есть фильтр «Действие» и «Показать
  события старее». Эти же события видны в общем «Журнале событий» (раздел
  «Акты инвентаризации»). Журнал акта доступен тем, кто видит итоги, даже без
  доступа к общему журналу.

- **Основное** — сводка акта (склад, дата, обновление из Quick Resto) и
  **общий комментарий к акту**: локальная заметка для команды, которая **не
  уходит в Quick Resto** и не перезатирается синхронизацией. Редактировать
  комментарий может управляющий актами, назначенный исполнитель или
  проверяющий; остальным он виден только для чтения. После правки внизу
  появляется полоса «Есть несохранённые изменения» с кнопками «Отменить» и
  «Сохранить»; уйти со страницы, не сохранив, приложение не даст без
  подтверждения. Комментарий из самого
  Quick Resto (если он есть) показывается тут же отдельным блоком.

### Дата и время акта

Дату и время акта можно поменять прямо в карточке, без похода в Quick Resto:
**Основное → Сведения → «Изменить дату»**. Выберите день и время и
подтвердите — они сохранятся в Quick Resto, и акт сразу перечитается оттуда.

- В «Сведениях» дата акта показана вместе со временем. Время — по часовому
  поясу заведения.
- **Время важно.** Quick Resto считает расчётный остаток на момент акта:
  поставки, продажи и списания после этого времени в расчётный остаток не
  попадают. Если подсчёт был вечером, а акт стоит на полдень, расчётный
  остаток будет без вечерних продаж.
- Кнопка есть у тех, кто управляет актами, и только у непроведённого акта.
  У проведённого акта дата только для чтения — он уже изменил остатки на
  свою дату. Если итоги акта утверждены, диалог подскажет сначала
  переоткрыть итоги.
- **Расчётные остатки пересчитаются.** После переноса меняются расчётный
  остаток, разница и суммы недостач и излишков по всем позициям. Введённые
  количества остаются как были. Если у акта уже есть введённые количества
  или итоги, диалог предупреждает об этом отдельно.
- Если Quick Resto не принял дату, причина остаётся в диалоге, а дата не
  меняется. Если дата сменилась, но позиции не перечитались, появится
  подсказка нажать «Синхронизировать».
- Смена даты попадает в журнал акта: кто, когда и с каких даты и времени на
  какие.
- «Последнее изменение в Quick Resto» в «Сведениях» — это когда акт последний
  раз сохраняли в Quick Resto (например, когда меняли дату или вводили
  количества). С датой акта это поле не связано.

## Действия в строке

- **Клик по строке** — открывает акт. По состоянию открывается нужный таб:
  незаполненный → Форма, проведённый/с готовыми итогами → Итоги.
- **№ акта (синяя ссылка)** — тот же переход, но явный.
- **Столбцы «Исполнитель» / «Проверяющий»** — у кого есть право назначать
  (`inventory.manage_documents`), меняют сотрудника прямо в строке (с учётом
  статуса — см. ниже «Исполнитель и проверяющий»).
- **Меню «⋯»** — «Открыть акт» и (для менеджера) «Удалить акт»; у акта с
  утверждёнными итогами и у акта, который ещё создаётся, пункта «Удалить» нет —
  вместе с таким актом пропали бы утверждённые итоги, пересорты и журнал
  решений. Проведённый акт удаляется с отменой проведения (см. «Удаление
  акта»). Это ограничение по состоянию акта, а не по правам: право удалять
  черновики никуда не девается. Удаление всегда подтверждается в диалоге;
  если сервер отказал, причина остаётся в диалоге. Исполнителя и
  проверяющего меняют прямо в столбцах, на телефоне — в карточке акта
  (поля «Исполнитель» и «Проверяющий»).

## Синхронизация с Quick Resto

Кнопка «Синхронизировать» в шапке — с выбором объёма в стрелке справа:

- **Только акты** — быстро, обновляет только список документов и их статусы.
- **Акты, ингредиенты и склады** — полная синхронизация.

Кнопка видна тем, у кого есть право синхронизации с Quick Resto.

**Акты приходят и без кнопки.** Раз в три часа приложение само делает полную
синхронизацию: непроведённые акты за последнюю неделю, номенклатура и склады.
Кнопка нужна, когда новый акт из Quick Resto нужен прямо сейчас.

**Акты, удалённые в Quick Resto, пропадают из списка автоматически.** При
синхронизации система помечает такие акты как архивные и скрывает их — провести
или редактировать удалённый акт нельзя. Если акт восстановят в Quick Resto,
следующая синхронизация вернёт его в список. Отдельно: при «Подвести итоги»
система проверяет, что акт реально существует и проводится в Quick Resto, —
если акт удалён или не провёлся, вы увидите ошибку, а не «тихий успех».

**Проведённый акт удалить нельзя.** Ни из «Опасной зоны», ни массово из списка:
вместе с актом пропали бы утверждённые итоги, пересорты и журнал решений — то
есть всё, чем можно объяснить закрытую инвентаризацию. Если акт действительно
больше не нужен, удалите его в Quick Resto: ближайшая синхронизация уберёт его и
здесь. При массовом удалении проведённые акты пропускаются, а в сообщении видно,
сколько именно пропустили.

**Акт чужого заведения недоступен.** Видимость актов и раньше ограничивалась
заведением, но действия (назначить, вернуть на пересчёт, подвести итоги, удалить)
эту границу не проверяли — теперь проверяют по тому же правилу, по которому акт
показывается в списке. Исключения прежние: назначенный исполнитель и проверяющий
работают со своим актом независимо от того, какое заведение у них выбрано.

**Массовые действия применяются к тому, что видно.** Если после выделения строк
включить фильтр или поиск, скрытые строки автоматически снимаются с выделения —
действие не уходит в позиции, которых нет на экране.

## Заполнение акта и итоги

При открытии акта на табе **«Форма»**:

- Пока акт **не проведён** в Quick Resto, подсчёт ведётся здесь, в CRM. Форма
  открывается **пустой** — нули из Quick Resto (которые там стоят у ещё не
  посчитанных позиций) в поля не подставляются. Поэтому прогресс «Заполнено
  X из Y» честно отражает, сколько строк вы реально ввели.
- **Заполнять могут исполнитель, проверяющий акта и управляющий актами.**
  Например, исполнитель уехал, позиции пересчитал другой сотрудник, а данные
  вносит проверяющий. Остальные видят форму только для чтения.
- Кнопка «Завершить» доступна, когда заполнены все строки; пока нет, рядом
  написано, сколько осталось. Неполный акт не примет и сервер: придёт
  сообщение «Заполнены не все позиции: осталось N», а акт останется в работе.
- **Черновик — свой у каждого.** Введённые числа сохраняются на устройстве
  под конкретного сотрудника. Если на общем планшете акт открывает другой
  человек (новый исполнитель, проверяющий), он видит форму без чужих
  незавершённых чисел. Черновики, сохранённые до этого изменения, достаются
  только исполнителю акта.
- **Синхронизация не стирает ваш подсчёт.** Если кто-то нажмёт
  «Синхронизировать», пока акт заполняется, уже введённые количества
  сохраняются, а незавершённый черновик на устройстве исполнителя не
  сбрасывается. Данные Quick Resto становятся главными только после того, как
  акт проведён.

На табе **«Итоги»** в шапке таблицы есть чекбокс **«выбрать все»** — отмечает
все доступные строки (с учётом активного поиска и фильтров; уже исключённые
из итогов и строки в пересорте не затрагиваются), чтобы быстро применить
массовое действие.

Под таблицей итогов — **пагинация** (25 / 50 / 100 строк на странице, как в
списке актов). Длинные акты больше не рендерятся одной простынёй. Текущая
страница **сохраняется**: после действия над строкой (например «Не учитывать»)
или обновления страницы браузера вы остаётесь там же, а не прыгаете на первую.
На первую страницу возврат только при смене фильтров/поиска/сортировки.

«Расчёт», «Разница» и «Упр. сумма» приходят из Quick Resto, привязаны к дате
акта и фиксируются при подведении итогов — почему это важно и что происходит при
пересчёте в другой день, см. [Итоги акта](./results.md).

Количества в Итогах (Расчёт / Факт / Разница) показываются **точнее денег** —
до сотых-тысячных, как ввёл исполнитель (хвостовые нули обрезаются: «4,15»,
«93»). Это важно: при округлении до десятых план и факт могли визуально
«сходиться», хотя по управленческой сумме оставалась разница. Денежные
колонки по-прежнему используют округление, заданное в настройках аккаунта.

## Колонки и пагинация

Колонки можно скрывать, переставлять и менять ширину — настройки сохраняются
в браузере. Ширину столбца нельзя сузить меньше его заголовка, а шапка таблицы
остаётся видимой при прокрутке. Сортировка по `№`, `Дата`, `Статус` — кликом по
заголовку (asc → desc → off). Сортировка по статусу идёт **по жизненному циклу**
(Новый → Назначен → В работе → Готов к проверке → На пересчёте → Итоги требуют
проверки → Проведен), а не по алфавиту. Пагинация:
25 / 50 / 100 строк на странице, при смене фильтра номер страницы
автоматически сбрасывается на 1.

### Исполнитель и проверяющий

Пока акт можно редактировать, в этих столбцах — выбор сотрудника (если у вас
есть право назначать). В списке выбора — только сотрудники с нужным правом в
заведении акта: исполнителем — с правом заполнять акты, проверяющим — с
правом возвращать на пересчёт; владелец аккаунта — всегда. Человек со второй
роли этого акта показан неактивным: исполнитель и проверяющий — разные люди.
**Исполнителя** можно менять только пока акт
заполняется/пересчитывается (Новый / Назначен / В работе / На пересчёте); после
того как акт ушёл «Готов к проверке», исполнитель залочен — чтобы передать
другому, отправьте акт на пересчёт. **Проверяющего** можно менять вплоть до
проведения. Подробнее — в [статусах акта](./statuses.md#кто-кого-назначает).

**Когда акт завершён** (проведён) или заблокирован, исполнитель и проверяющий
становятся ссылками: клик открывает страницу сотрудника напрямую, а стрелка
«‹» перед путём в верхней панели ведёт обратно в «Акты инвентаризации». Ссылка появляется только если
у вашей должности есть **доступ к разделу «Сотрудники»**; иначе просто имя.

### Итоги

Одно число — нетто-расхождение по акту (излишки минус недостачи). **Плюс**
(излишек) подсвечивается зелёным, **минус** (недостача) — красным. Прочерк —
если у акта ещё нет посчитанных итогов.

Это **управленческие итоги** — то, что реально учитываем: с учётом исключённых
строк и активных пересортов (как «Управленческая оценка» в карточке акта), а не
сырые данные из Quick Resto. Считается из позиций акта, поэтому у проведённых
актов больше не стоит «0,0 ₽» (Quick Resto не заполняет итог на уровне
документа).

### Метка «итоги правились после проведения»

Иногда проведённый акт **разблокируют** и правят итоги (исключают позицию,
делают пересорт). После этого управленческие итоги в CRM могут **разойтись** с
тем, что реально проведено в Quick Resto. Такие акты помечаются **жёлтым
треугольником ⚠️** рядом со статусом — и в списке, и в шапке самого акта
(«Итоги правились после проведения»). Это сигнал владельцу: посмотреть журнал
акта, кто и что менял после проведения. Любое такое изменение по-прежнему
пишется в **Журнал** акта.

## Кто что видит — модель доступа

- **Линейный сотрудник** (только `inventory.fill_assigned_documents`): видит
  только акты, назначенные на него; фильтра «Назначен» нет; меню «⋯» без
  «Изменить назначение». **Итоги** такого акта он видит **только после того,
  как акт проведён** — во время заполнения и проверки они ему недоступны
  (анти-подгонка). Таб «Итоги» read-only: исключать/пересортировать/обновлять
  итоги он не может (нет прав), только смотреть.
- **Менеджер** (`inventory.view_documents` + `inventory.manage_documents`,
  но без `view_all_venues`): видит акты заведений своего членства, может
  переназначать.
- **Менеджер с расширенным доступом** (`+ inventory.view_all_venues`):
  видит все акты аккаунта.
- **Владелец**: всё.

Это разграничение действует и при **открытии акта по прямой ссылке**: акт
заведения, к которому у вас нет доступа, не откроется через URL — будет
переадресация на список (исключение — акт, назначенный лично вам).

> **Важно: заведение акта берётся от его склада.** Каждый акт привязан к
> заведению через свой склад (поле «Заведение» склада в **Организация →
> Склады**). Если склад **не привязан** к заведению, у его актов нет
> заведения — и тогда их видят только пользователи с правом «Все заведения»
> (`inventory.view_all_venues`) или «Управление складами»
> (`inventory.manage_stores`). Поэтому сотрудник, которому выдали лишь
> «Просмотр актов», может видеть **пустой список**, хотя у владельца всё на
> месте. Решение: привязать склады к заведению в **Организация → Склады**.
> Склады из интеграции QuickResto привязываются к подключённому заведению
> **автоматически** при синхронизации; ручная привязка нужна лишь в редких
> случаях (например, в аккаунте несколько заведений и нет связи с QuickResto).

## Известные ограничения

- Сумма итогов по выделению считается по строкам **текущей страницы** (не по
  всей выборке за период/склад). Агрегат по всему фильтру — в планах.
- Сохранённые «виды» (именованные фильтры) и зонная inbox-сортировка — в
  бэклоге, пока не реализованы.
- Автоматическая **отправка** акта на пересчёт — в плане. Сам автодетект
  больших расхождений уже работает: пороги настраиваются у заведения, строки
  помечаются автоматически, см. [Возврат на пересчёт](./recount.md#пороги-авто-маркера).
  Автоматической остаётся только пометка — решение вернуть акт принимает человек.

## Если Quick Resto временно ограничил отправку

Большой акт отправляется небольшими частями с паузами. Приложение продолжает
отправку само; черновик удаляется только после завершения всего акта. Если Quick Resto
просит подождать, приложение выдерживает паузу и повторяет отклонённый запрос.
Если ограничение сохраняется, акт остаётся в работе, а черновик — на том же
устройстве. Подождите и повторите отправку: принятые Quick Resto количества
будут пропущены. Не очищайте данные браузера до успешной отправки акта.

## Удаление акта

Акт удаляется **и в Sheerly, и в Quick Resto** — из «Опасной зоны» карточки,
из меню «⋯» строки или из панели выделенных актов.

- Сначала акт удаляется в Quick Resto, потом у нас. Если Quick Resto удаление
  не подтвердил (не ответил, нет прав у пользователя Sheerly Bot), акт
  остаётся и там, и здесь, а окно подтверждения пишет причину — можно
  повторить через минуту. Удалить только у нас нельзя: синхронизация вернула
  бы акт обратно.
- **Проведённый акт** удаляется по одному, через отмену проведения. Окно
  называется «Отменить проведение и удалить акт № …?» и прямо говорит, что
  остатки склада пересчитаются: недостача и излишки по акту уйдут. Сначала
  Sheerly отменяет проведение в Quick Resto, ждёт, пока Quick Resto её
  закончит, и только потом удаляет акт — там и здесь. Если отмена прошла, а
  удалить не удалось, окно так и скажет: акт остался непроведённым и там, и
  здесь, удаление можно повторить. Если акт проведён в Quick Resto, а у нас
  это ещё не видно (синхронизация не успела), окно попросит обновить страницу.
  При удалении нескольких актов проведённые пропускаются — их удаляют по
  одному из меню «⋯».
- **Акт с утверждёнными итогами** не удаляется никак: вместе с ним пропали бы
  итоги, пересорты и журнал решений, на которых держатся удержания.
- Удаление проведённого акта меняет удержания по недостаче за его месяц —
  они пересчитываются (если автопересчёт удержаний включён).
- Пока акт создаётся (позиции добавляются в фоне), удалить его нельзя.
- Если акт в Quick Resto уже удалили вручную, у нас он просто удаляется.
- При удалении нескольких актов каждый проходит этот путь отдельно: что Quick
  Resto не удалил, остаётся, остальные удаляются, а в сообщении — сколько и
  почему осталось.
- В общем журнале событий остаётся запись «удалил(а) акт инвентаризации … · и
  в Quick Resto» (у проведённого — «с отменой проведения») с номером, датой и
  складом. Отменить удаление нельзя.
