# Экраны интеграций: Tilda, Telegram, Quick Resto

## Зачем
Экраны «Настройки → Интеграции» выглядели разрозненно и непонятно: «Тильда» кириллицей, без логотипов, загадочные «Требуют проверки: 16» и «Заменить ключ», у Quick Resto при рабочем подключении — снова мастер с шага 1 и временная кнопка диагностики. Цель — логично, минималистично, в стиле Sheerly DS. Прототип согласован с пользователем (artifact VLSWqEVqaHkZtU33qAbrm1), правки: официальные логотипы с quickresto.ru и tilda.cc, меньше текста.

## Решения
- **Логотипы** — официальные SVG (Tilda, Quick Resto, Telegram) inline-компонентом `IntegrationLogo`; знак Tilda на `currentColor`, чтобы читался в тёмной теме.
- **Хаб** — карточки с логотипом, статус («Работает» / «Требует внимания» / «Не настроено» / «Выключено»), одна строка описания, одна строка факта. Если есть недоставленные уведомления — плашка сверху со ссылкой на Telegram.
- **«Требуют проверки»** заменено журналом «Не доставлено» на экране Telegram: ошибочные задания `notify`, `hired`, `chat_invites`. Действия: «Отправить снова» (сброс попыток и флага неподтверждённой отправки) и «Не отправлять» (закрыть задание). На Tilda — плашка «N уведомлений о новых анкетах не дошли» со ссылкой.
- **Tilda** — латиницей; приём включается переключателем в шапке; подключение — три шага (ID формы, адрес приёмщика, ключ). «Заменить ключ» → «Выпустить новый ключ» с объяснением и подтверждением.
- **Telegram** — бот; «Не доставлено»; «Уведомления» (событие → чат, правка в боковой панели); «Чаты сотрудников» (список, действия в ⋯, форма в боковой панели). ID чата по-прежнему вводится вручную, с подсказкой где его взять.
- **Quick Resto** — при рабочем подключении сводка (учётная запись API, сотрудник бэк-офиса, последняя проверка) и кнопки «Загрузить данные» (мастер с шага выбора данных) и «Переподключить» (мастер с шага 1). Кнопка синхронизации — в шапке. Временная кнопка диагностики номенклатуры удалена.
- **Справка «?»** — записи в `PAGE_HELP_ENTRIES` для хаба, Tilda, Telegram, Quick Resto.

## Не делаем
- Автообнаружение чатов ботом (нужен webhook Telegram) — отдельная задача.
- Изменения схемы БД.

## Подходы
1. Переписать экраны поверх существующих server actions + один новый action для журнала (выбран: минимум риска, без миграций).
2. Общий конструктор «экрана интеграции» с декларативными шагами — избыточно для четырёх экранов.
