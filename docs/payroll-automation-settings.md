# Настройки автоматизаций зарплаты и передача исполнения

Настройки доступны в **Заведение → Оплата труда → Медкнижки, форма и мотивация**.
Права чтения и изменения — `payroll.configure` для активного заведения. Каждое сохранение
создаёт неизменяемую для приложения версию с автором и временем, а также событие
`payroll.automation_settings.updated` общего журнала. Конфликт версий отклоняется.

Это подготовка конфигурации, **не переключение исполнителя**. Worker не читает эти
настройки, существующие правила n8n не меняются, записи Fees не переисполняются.
В интерфейсе явно показано «Исполняет n8n». Первая загрузка без сохранённой записи
показывает шаблон CHILLING из проверенных источников; для другого заведения его
необходимо проверить. Сохранение не создаёт удержаний, подарков или QR-операций.

## Перенесённая конфигурация

- Медкнижка: напоминание через 3 дня после приёма и за 30 дней до окончания срока;
  непредоставленная книжка — 3 000 ₽ через месяц; просрочка — **один штраф 3 000 ₽
  за случай**, по решению владельца 16.10.2026; компенсация 3 000 ₽ через 3 месяца
  после обследования, при условии обследования после приёма. Дата обследования и
  дата окончания срока — разные поля. Старый n8n всё ещё штрафует ежедневно;
  изменение его поведения относится к передаче исполнения.
- Форма: 4 удержания, 3 и 18 числа. Стоимость относится к конкретной покупке;
  последняя часть должна закрывать остаток. Одно приобретение — один расход,
  удержания не создают повторные расходы.
- Задачи: штраф по умолчанию 200 ₽ либо предупреждение; премия за подтверждённое
  выполнение перенесённой задачи, сумма из задачи, бонусами по умолчанию.
- Подарки: день рождения, Новый год, день бармена, 23 февраля, 8 марта, день кальянного
  мастера; две суммы с границей стажа 90 дней, ежегодная дата и получатели.
- Подарки за стаж: точные пороги 60/120/180/270/366/550/770 дней. Подарки и целевые
  скидки отдельно от зарплатных надбавок должности. Назначение скидки в QR ещё не
  подключено: старый n8n только упоминает её в поздравлении.

Исходные названия должностей сохранены в конфигурации как проверяемый список.
До подключения исполнителя необходимо сопоставить их с ID/семействами должностей
Sheerly, включая старших сотрудников. Нельзя молча менять получателей относительно
источника; старые ветки дня рождения/стажа фактически игнорировали фильтр должностей.

Источники: Notion «Праздники» `99c9a4c2-7cab-409e-b4b8-9b2983389830`,
«Стаж работы» `d94b24bd-996a-4ab4-85bd-01774ec671f0`, страница дня рождения
`b57adfd1-11c5-4f05-a019-43e818788f43`; n8n CHILLING, аудит 16.10.2026.

## Что выявлено в Glide/n8n

- Изменение сотрудника, flow `NGnGN6qIzqH1Ni0MUab5`, направлено в `site-forms`
  (заявки сайта), вместо профильного обновления сотрудника.
- Изменение записи должности, flow `rYef85hwCBevyjBNti36`, содержит старый Make
  webhook. Владелец подтвердил, что Make уже не работает. Секретный URL не хранится.
- Удаление бонусного штрафа вызывает `fine-refund-bonuses`; Glide передаёт Row ID,
  но n8n не связывает возврат с подтверждённым исходным дебетом.
- `fee-split` проверяет бонусный тип и всегда делает credit. Бонусный штраф через
  этот вход потенциально зачисляется. Доступность такого выбора в опубликованной
  форме отдельно не доказана.
- В «ID операции» Fees записан ID Telegram-сообщения, не QR-проводки. Сбой после
  принятого QR-запроса и до отправки Telegram/отметки допускает повторное списание.
- Счётчик предупреждений n8n использует только неотправленные записи; часть уже
  учтённых предупреждений выпадает из месячной эскалации.
- Подарки читают числовые поля Notion как rich_text, поэтому по текущему коду сумма
  может стать нулевой. Фактическая история QR по всем подаркам не сверена.
- Создание сотрудника, обработка оборота/смен и оркестратор дня смешивают зарплату
  с QR, Adesk и аналитикой. Нельзя отключить их целиком ради зарплаты.

## Условия полного перехода

1. Исполнитель бонусов Sheerly: журнал исходных/обратных операций, стабильный ключ
   события, сериализация по бонусному счёту, проверка результата QR. Неопределённый
   ответ переводит запись на сверку, а не запускает повторный POST.
2. Перенести исполнение задач, медкнижек, формы и подарков, включая реальное состояние
   задач, уже оплаченные компенсации, покупки формы и обработанные подарки.
3. Выбрать точное время передачи. История до 15.10 и новые зарплатные правила с 16.10
   уже согласованы; это **не** время включения реальных бонусных списаний.
4. Закрыть старые Glide Actions/webhook и зарплатные вызовы n8n; дождаться завершения
   running/waiting, запретить повтор старых финансовых исполнений; сверить хвост по ID.
5. Только затем включить нового владельца QR-списаний. Старые imported/done/review
   не попадают в новую очередь. ID Telegram не даёт права автоматически вернуть бонусы.
6. Общие инкассации, гостевая лояльность и не перенесённые финансовые ветки сохраняются.
   Sheerly не синхронизирует новые выплаты в Adesk автоматически.

Реальные QR-списания остаются у n8n, Sheerly — в `bonus_mode=parallel`. В ходе
подготовки настроек финансовые операции не выполнялись, workflows не публиковались
и не отключались.
