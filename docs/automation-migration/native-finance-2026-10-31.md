## Поведение

- Восьмое направление существующего обработчика смен, без запросов записи в
  Quick Resto/Adesk. Включает владелец с доступом к продажам и финансам:
  текущий/будущий день, настроенные счета, автоматическое чтение и подтверждение
  остановки старых обработчиков и сверки остатков/связей.
- Перед записью перепроверяются заведение, подключение, источник, правила,
  журнал и захват задания. Вся цепочка, остатки, связи и история атомарны.
  Остатки меняет существующий механизм транзакций. Ошибка откатывает всю цепочку.
- Связь с источником хранится отдельно: Adesk ID/банковские связи сохраняются.
  Подтверждённый импорт связывается без движения денег. Неоднозначность, дубли,
  недостающая связь и отменённая похожая операция блокируют проведение.
- Повтор запроса возвращает прежний результат. При обрыве ответа читается
  результат именно этого запроса, без слепого повторного финансового действия.
- Позднее такси добавляет только непокрытые номера, не весь расход дня повторно.
- Первое проведение закрепляет правила дня. Новые комиссии/счета не меняют
  прошлое. Актуальными остаются решения по отдельным кассовым номерам.
  Сверка карточки дня использует те же закреплённые правила.
- Коррекция требует совпадения с последним состоянием автоматики: суммы, счета,
  статья, тип, дата, описание, валюта, юрлица, контрагент, источник и отмена.
  Ручная правка видна конфликтом сразу. Восстановление возможно только после
  собственной отмены при возврате. Ручная отмена не восстанавливается.
- Операция до контрольного остатка счёта или перенос связанного кассового номера
  в другой день требуют сверки. Междневная автокоррекция не включена.
- Обычная история транзакции хранит создание/правки/отмену/восстановление,
  поля до/после, причину, источник, номер проведения. Ручные правки импортированных
  связанных операций тоже журналируются. Статусы и история — в существующей
  карточке смены; отдельного рабочего экрана нет.

## Проверки и граница готовности

Чистый калькулятор проверяет коррекции/возвраты/восстановления, ручные решения,
связи, части такси и поздние номера. SQL с полным откатом проверяет реальные
остатки: 100 → 150 ₽, сохранение ручных 160 ₽, возврат → 0 ₽, восстановление
→ 150 ₽; атомарность, устаревший снимок/захват, закреплённые правила, выключение
после подготовки. Отдельно проверены полные цепочки такси, точные остатки двух
счетов, сохранение Adesk ID, права читателя без сырых снимков/включения, область
заведения и закрытые API записи. Чистая установка миграции проверена с откатом.

Прежние сверки и кассовые уведомления прошли с восемью очередями. TypeScript,
ESLint и новые объекты локальных advisors/lint без замечаний. В браузере сохранён
только выключенный режим сверки: история работает, ширина 390 px без переполнения.
