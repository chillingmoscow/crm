# Возврат акта на пересчёт

Когда менеджер на странице «Итоги» видит подозрительные расхождения (большие минусы по одной позиции, странные цифры по группе), он может **вернуть акт исполнителю на повторный счёт**. Эта механика помогает не подгонять числа «лишь бы сошлось», а действительно перевзвешивать там, где много не сошлось.

## Кто может отправлять на пересчёт

Право `inventory.recount_documents` (модуль «Акты инвентаризации»). По умолчанию выдаётся ролям _Менеджер_ и _Администратор_. Линейному сотруднику (хост, официант) это право не нужно — он пересчитывает то, что ему пометили.

## Как это работает

1. **Авто-маркер.** Система сама подсвечивает строки с большим расхождением. Порог задаётся на уровне заведения (см. ниже). Маркер срабатывает **только на сосчитанных строках** (где введён факт) — пока позицию не посчитали, она не помечается на пересчёт.
2. **Ручная пометка.** Менеджер на «Итогах» каждую строку может вручную переключить флажок «Пересчёт». Если автомат отметил неправильно — снимает; если что-то заподозрил сам — ставит.
3. **Отправка на пересчёт.** Когда хотя бы одна строка помечена, кнопка «Отправить на пересчёт» становится активной. Клик — и акт меняет статус на **«На пересчёте»**, исполнитель получает его обратно.
4. **Исполнитель видит баннер** «Акт вернули на пересчёт» на странице «Форма». Помеченные строки подсвечены rose-tone. Исполнитель пересчитывает их и нажимает «Завершить пересчёт».
5. **Возврат в «Готов к проверке».** После повторного submit'а акт снова приходит к менеджеру. Если новое расхождение тоже больше порога — автомаркер снова отметит. Так может повторяться, пока числа не сойдутся.

## Пороги авто-маркера

Настраиваются на уровне заведения. Открыть _Заведения → конкретное заведение → Основное → секция «Инвентаризация»_:

- **Порог по сумме, ₽** — например, 500. Если расхождение по строке в денежном выражении больше — автомаркер ставит флаг.
- **Порог по проценту, %** — например, 10. Если относительное расхождение (|разница| / расчётное количество × 100%) больше — автомаркер ставит флаг.

Логика — OR: если **любой** из двух порогов перекрыт, строка помечается. По умолчанию 500 ₽ / 10 %.

Ручные пометки менеджера «защищены» от автомаркера: если менеджер сам поставил/снял флаг, автоматика не перезатрёт его при следующем обновлении расхождений.

## Что происходит после submit'а исполнителем

- Все флаги «Пересчёт» сбрасываются на строках, по которым исполнитель отправил значение.
- Автомаркер сразу же снова проверяет пороги — если новое значение опять «подозрительно», флаг встаёт автоматически.
- Локальный черновик (IndexedDB) исполнителя инвалидируется через `last_returned_at`: даже если он накопил в браузере старые цифры до возврата, эти данные не перезатрут актуальные значения с сервера.

## Лимиты

- Из статуса **«Проведён»** (закрыт в Quick Resto) вернуть нельзя — QR-side уже залочен.
- Из статуса **«На пересчёте»** повторно отправить на пересчёт нельзя — акт уже у исполнителя.
- Чекбокс возвращён? Да — менеджер всегда может его снять до отправки. После отправки строка ушла исполнителю, флаг остаётся пока тот не пересчитает.

## История

Каждый возврат пишется в журнал акта (вкладка «Журнал»):

- `recount_marked` / `recount_unmarked` — ручные правки менеджера на строках.
- `returned_for_recount` — отправка всего акта на пересчёт. В payload — список ID помеченных строк и счётчик `recount_count` (сколько раз акт уже возвращали).

Если один акт прошёл несколько кругов пересчёта, в журнале видна вся цепочка.
